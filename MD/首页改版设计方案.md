# 首页改版设计方案

> 状态：设计提案，待确认后实施
>
> 版本：1.0
>
> 日期：2026-10-18

## 1. 改版背景

当前 `web/src/views/HomeView.vue` 仍是脚手架式首页，只展示写死的“用户总数、今日访问、待办事项、系统消息”和通用欢迎语。它不能反映 FullstackSeed 已经具备的 Agent、客服、知识库、审批、产品与 SKU 等核心业务，也不能帮助不同岗位快速进入当天工作。

本次首页不定位为纯数据大屏，而定位为：

1. **工作入口**：让用户一眼找到最常用模块。
2. **待办中心**：优先暴露需要人工处理的事项和真实异常。
3. **运营概览**：通过少量高价值指标和 ECharts 图表观察近期变化。
4. **业务资产看板**：展示 Agent、知识库、产品、SKU 等核心资产的规模与健康度。

首页必须保持“可操作、可解释、可追溯”。没有可靠数据来源的指标不展示，不用静态数字或前端推算冒充真实业务统计。

## 2. 设计目标与边界

### 2.1 目标

- 首页数据全部来自真实聚合接口，移除硬编码占位数字。
- 将“需要处理的事情”放在单纯的总量统计之前。
- 增加产品与 SKU 统计，支持品类分布和单产品 SKU 数量排行。
- 使用 ECharts 展示 Agent 执行趋势、商品/SKU 分布、客服任务趋势和知识库健康度。
- 根据当前用户权限动态展示模块，避免无权限数据泄露。
- 在主菜单占用横向空间后，首页仍能在常见分辨率下清晰呈现。
- 图表和数字可下钻到对应管理页，并携带可识别的筛选条件。

### 2.2 非目标

- 第一版不支持拖拽、自定义组件、个人保存布局。
- 不在首页重造产品、SKU、执行记录、审批等 CRUD 表格。
- 不展示当前数据结构无法支持的库存、销量、销售额、毛利等指标。
- 不根据 SKU 数量推断库存，不把产品启用状态描述为在售状态。
- 没有完整价格目录时不估算模型费用；供应商未返回 Token 时不补算 Token。
- 第一版不建设独立实时数仓，不引入 WebSocket 大屏推送。

## 3. 首页定位

建议使用“**运营工作台**”作为产品定位，但路由标题继续保持“首页”，避免与左侧具体的 Agent 工作台、客服工作台混淆。

首页回答四个问题：

1. 今天有什么需要处理？
2. 系统今天运行得怎么样？
3. 核心业务资产规模和状态如何？
4. 我下一步可以去哪里操作？

## 4. 信息架构

### 4.1 推荐桌面布局

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 上午好，管理员    近 7 天 / 近 30 天          数据时间 10:32  [刷新] │
│ 当前有 3 项待处理，1 项运行异常                                     │
├───────────┬───────────┬───────────┬───────────┬───────────┬──────────┤
│ 今日执行  │ 成功率    │ 待接待    │ 待审批    │ 产品总数  │ SKU 总数 │
│ 128       │ 96.2%     │ 2         │ 3         │ 86        │ 412      │
│ 较昨日…   │ 失败 4    │ 最久 8m   │ 最久 2h   │ 启用 80   │ 启用 397 │
├──────────────────────────────────────────────┬───────────────────────┤
│ Agent 执行趋势（ECharts，8 栅格）            │ 业务健康概览（4 栅格）│
│ 柱：执行量；线：成功率；Tooltip：Token/耗时  │ Agent/知识/商品/客服  │
├───────────────────────────────┬──────────────┴───────────────────────┤
│ 产品 / SKU 品类分布（ECharts）│ 客服 AI 任务趋势（ECharts）          │
│ 横向分组柱状图 + SKU Top 产品 │ 任务量、成功、失败                    │
├───────────────────────────────┼──────────────────────────────────────┤
│ 知识库健康度（ECharts）       │ 待办与异常                            │

└───────────────────────────────────────────────────────────┴──────────┘
```

### 4.2 页面层级

页面从上到下按“紧迫程度 → 趋势判断 → 资产结构 → 操作入口”排序：

1. 欢迎与全局时间范围。
2. 六个核心指标。
3. Agent 执行趋势和业务健康概览。
4. 产品/SKU 与客服趋势。
5. 知识库健康、待办异常、最近动态和快捷入口。

首页较长时允许正常页面滚动，不把所有内容强行压缩进一屏。

## 5. 核心指标设计

### 5.1 顶部六项指标

| 指标 | 主值 | 辅助信息 | 点击去向 | 权限 |
| --- | --- | --- | --- | --- |
| 今日 Agent 执行 | 今日创建的执行数 | 较昨日增减；执行中数量 | Agent 执行记录，日期=今天 | `AgentApp.read` |
| Agent 成功率 | `succeeded / (succeeded + failed)` | 今日失败数；取消数单列提示 | Agent 执行记录，日期=今天 | `AgentApp.read` |
| 等待人工 | 当前 `waiting_human` 会话数 | 最长等待时长 | 客服工作台，状态=等待人工 | `CustomerService.read` |
| 待审批 | 当前 `pending` 审批数 | 最早提交等待时长 | 审批管理，状态=待审批 | `ApprovalRequest.read` |
| 产品总数 | 未软删除产品总数 | 启用 / 停用数量 | 产品库 | `Product.read` |
| SKU 总数 | 未软删除 SKU 总数 | 启用数；平均每产品 SKU 数 | SKU 库 | `ProductSku.read` |

规则：

- 无权限的指标不显示，剩余卡片自动重新排布，不保留空槽。
- 没有数据时显示 `0`；数据接口不可用时显示 `--` 和“暂不可用”，不能显示 `0`。
- 增减比例必须有完整可比周期；当天未结束时，今日与昨日比较采用相同时间截点。
- 成功率分母不包含 `cancelled`，取消数量在 Tooltip 中单独展示。
- 顶部卡片只使用数字和一句辅助信息，不放迷你图，避免重复表达下方趋势图。

### 5.2 业务健康概览

右侧使用四行紧凑状态，而不是第二组大号 KPI：

- Agent：启用应用数 / 应用总数，当前运行中，今日失败。
- 知识库：已可用文档、处理中、待处理、异常。
- 商品：启用产品、停用产品、启用 SKU、停用 SKU。
- 客服：AI 会话、等待人工、人工接待、已关闭。

每行均可点击进入对应模块。红色仅用于真实异常，橙色用于待处理，蓝色用于正常运行中的状态，绿色用于已成功或健康状态。

## 6. ECharts 图表设计

### 6.1 Agent 执行趋势

推荐使用柱线组合图：

- X 轴：自然日，默认近 7 天，可切换近 30 天。
- 左 Y 轴柱状图：每日执行总量。
- 右 Y 轴折线图：每日成功率。
- Tooltip：总量、成功、失败、取消、记录到的 Token、平均模型调用耗时。
- 图例只保留“执行量、成功率”，详细状态放入 Tooltip，避免图例过多。

Token 必须同时返回覆盖量，例如 `tokenReportedExecutions`。当供应商未返回用量时不按字符估算；覆盖量为 0 时显示“暂无 Token 用量回执”。

### 6.2 产品与 SKU 分布

主图使用横向分组柱状图：

- Y 轴：产品品类，按 SKU 数降序取前 8 项。
- 系列一：该品类产品数。
- 系列二：该品类 SKU 数。
- 空品类统一显示“未分类”。
- 超出前 8 项的品类聚合为“其他”。
- Tooltip 明确单位，避免把 SKU 数误解为库存。

图表右上角提供“按品类 / SKU Top 产品”切换：

- “按品类”展示产品数与 SKU 数分布。
- “SKU Top 产品”展示 SKU 数最多的前 10 个产品。
- 同数量时按产品 ID 升序保证结果稳定。

配套摘要：

- 产品总数、SKU 总数。
- 启用 SKU 数、停用 SKU 数。
- 平均每产品 SKU 数，产品数为 0 时返回 0。
- 无 SKU 产品数，帮助发现尚未完善规格的产品。

当前实体没有库存、价格和销量字段，因此第一版明确不出现“库存总量、缺货 SKU、销售额、热销商品”等文案。将来新增库存流水或订单模块后再独立扩展，不能复用现有 SKU 数冒充。

### 6.3 客服 AI 任务趋势

使用堆叠柱状图或多折线图：

- 每日 AI 任务总数。
- 完成任务数。
- 失败任务数。
- 取消/过期任务数。

当前会话只保存最新服务状态，没有完整的状态变更事件流，因此首页不统计历史“转人工率”或“平均等待人工时长趋势”。顶部“等待人工数”和“最长等待时长”仅计算当前快照。若后续新增客服状态事件表，再补转人工和接待时效趋势。

### 6.4 知识库健康度

使用环形图展示当前知识资产状态：

- 可用：已完成解析、分片和索引，可用于检索。
- 处理中：任一处理阶段正在执行。
- 待处理：尚未完成必要处理。
- 异常：解析、分片或索引存在明确失败。
- 未识别：历史或未知状态，不能归入成功。

后端必须集中维护实际 `processStage`、`parseStatus`、`chunkStatus`、`indexStatus` 到上述展示状态的映射，并为未知值保留计数，前端不自行猜测字符串。

### 6.5 图表公共交互

- 使用 ECharts 5，采用 `echarts/core` 按需注册 `BarChart`、`LineChart`、`PieChart`、`CanvasRenderer`、`GridComponent`、`TooltipComponent`、`LegendComponent` 和 `AriaComponent`。
- 图表容器通过 `ResizeObserver` 自适应卡片宽度，并在组件卸载时 `dispose`。
- 支持系统 `prefers-reduced-motion`，减少或关闭入场动画。
- 开启 ECharts ARIA；Tooltip 内容同时能通过卡片摘要理解，不能只有悬浮后才有关键结论。
- 图表加载使用骨架屏；空数据展示业务化空状态；单个图表失败只影响该卡片，并提供重试。
- 不使用 3D 图、仪表盘、玫瑰图和大面积渐变；避免装饰性视觉干扰数据阅读。
- 图表颜色建议：品牌蓝 `#409EFF`、成功绿 `#67C23A`、警告橙 `#E6A23C`、异常红 `#F56C6C`、中性灰 `#909399`。红色和橙色只表达异常或待处理。

## 7. 待办、最近动态与快捷入口

### 7.1 待办与异常

待办列表最多展示 8 条，优先级建议：

1. 等待人工客服，按等待时间倒序。
2. Agent 失败或租约恢复记录，按发生时间倒序。
3. 知识文档处理失败。
4. 待审批记录，按提交时间升序。

每项显示模块、标题、状态、发生或等待时间，以及“去处理”入口。首页不直接执行审批、删除、接待等有副作用操作。

### 7.2 最近业务动态

优先复用日志记录中的模块、动作、摘要、操作人和时间，展示最近 10 条当前用户有权查看的动态。日志中没有可靠业务标题时只展示安全摘要，不读取或拼接敏感参数。

若当前用户没有日志权限，则该区域隐藏，快捷入口扩展占用其空间。

### 7.3 快捷入口

快捷入口由前端根据路由和 `userStore.hasPermission()` 生成，不需要后端返回：

- Agent 工作台
- Agent 应用管理
- 客服工作台
- 上传或管理知识文档
- 产品库
- SKU 库
- 审批管理

第一版最多显示 6 个，按业务优先级固定排序；后续再考虑最近使用或用户收藏。

## 8. 权限与个性化规则

首页路由继续允许所有已登录用户访问，但每个数据区块沿用所属模块的读取权限：

| 区块 | 所需权限 |
| --- | --- |
| Agent 指标与趋势 | `AgentApp.read` |
| 客服指标与趋势 | `CustomerService.read` |
| 审批待办 | `ApprovalRequest.read` |
| 产品指标 | `Product.read` |
| SKU 指标与分布 | `ProductSku.read` |
| 知识库健康 | `KnowledgeBase.read` |
| 最近日志 | 对应日志读取权限及业务模块读取权限 |

后端根据当前用户权限决定是否查询并返回区块，前端隐藏未返回区块。不能先返回完整数据再仅通过 CSS 隐藏。超级管理员可查看全部区块。

首页不是按角色名称硬编码，而是按权限组合自适应：

- 客服岗位重点看到待接待、客服任务趋势和客服入口。
- 知识运营重点看到知识健康、审批待办和知识入口。
- 商品运营重点看到产品/SKU 指标与分布。
- Agent 管理员重点看到执行趋势、失败和 Token/耗时。

## 9. 聚合接口建议

### 9.1 接口

```http
GET /api/dashboard/overview?days=7
```

- `days` 仅允许 `7` 或 `30`，默认 `7`。
- 需要登录，不新增笼统的 `Dashboard.read` 权限。
- 每个区块继续使用原业务模块的读取权限。
- 返回 `generatedAt`，前端明确展示数据更新时间。
- 使用 `Asia/Shanghai` 自然日计算今日、昨日和趋势日期边界。

### 9.2 建议契约

```ts
export interface DashboardOverview {
  generatedAt: string;
  timezone: 'Asia/Shanghai';
  period: {
    days: 7 | 30;
    startDate: string;
    endDate: string;
  };
  sections: {
    agent?: DashboardSection<AgentDashboardData>;
    customerService?: DashboardSection<CustomerServiceDashboardData>;
    approvals?: DashboardSection<ApprovalDashboardData>;
    catalog?: DashboardSection<CatalogDashboardData>;
    knowledge?: DashboardSection<KnowledgeDashboardData>;
    activities?: DashboardSection<ActivityDashboardData>;
  };
}

export interface DashboardSection<T> {
  status: 'ready' | 'unavailable';
  data: T | null;
  message?: string;
}

export interface AgentDashboardData {
  todayTotal: number;
  running: number;
  succeeded: number;
  failed: number;
  cancelled: number;
  successRate: number | null;
  totalTokens: number | null;
  tokenReportedExecutions: number;
  averageModelCallDurationMs: number | null;
  trend: Array<{
    date: string;
    total: number;
    succeeded: number;
    failed: number;
    cancelled: number;
    successRate: number | null;
    totalTokens: number | null;
    tokenReportedExecutions: number;
    averageModelCallDurationMs: number | null;
  }>;
}

export interface CatalogDashboardData {
  productTotal: number;
  enabledProducts: number;
  disabledProducts: number;
  skuTotal: number;
  enabledSkus: number;
  disabledSkus: number;
  productsWithoutSku: number;
  averageSkusPerProduct: number;
  categoryDistribution: Array<{
    category: string;
    productCount: number;
    skuCount: number;
  }>;
  topProductsBySku: Array<{
    productId: number;
    productName: string;
    skuCount: number;
  }>;
}
```

客服、审批和知识库区块使用同样的 `summary + trend/distribution + todoItems` 思路。前后端字段必须保持 camelCase 一致，分页列表仍使用 `{ list, total }`；首页聚合接口不是分页 CRUD，不复用列表页返回结构。

### 9.3 部分失败

聚合服务建议按区块执行并安全收敛结果：

- 无权限：不返回该区块。
- 查询成功：`status: 'ready'`。
- 单一区块查询失败：`status: 'unavailable'`，返回安全提示并记录服务端日志。
- 鉴权或聚合入口本身失败：接口整体失败。

这样某个业务模块短暂异常时，首页其他区域仍可使用。

### 9.4 性能原则

- 使用 `COUNT`、条件聚合和有限 `GROUP BY`，不加载完整实体后在 Node.js 内计数。
- 趋势范围最大 30 天，品类最多 8 项，产品排行最多 10 项，待办和动态最多 10 条。
- 各业务区块可并行查询，但应受数据库连接池能力约束。
- 第一版不强制缓存；上线后根据慢查询和调用量决定是否增加 15～30 秒短缓存。
- 用户相关待办不能与其他用户共享缓存；系统级统计若缓存，缓存键必须包含权限区块集合。
- 新增索引必须以实际 `EXPLAIN` 和慢查询为依据，不为首页预先堆叠索引。

## 10. 前端组件建议

```text
web/src/
├─ api/dashboard.ts
└─ views/
   ├─ HomeView.vue
   └─ home/components/
      ├─ DashboardHeader.vue
      ├─ DashboardMetricCard.vue
      ├─ DashboardSectionCard.vue
      ├─ AgentExecutionTrend.vue
      ├─ CatalogDistributionChart.vue
      ├─ CustomerTaskTrend.vue
      ├─ KnowledgeHealthChart.vue
      ├─ DashboardTodoList.vue
      ├─ DashboardActivityList.vue
      └─ DashboardQuickActions.vue
```

原则：

- `HomeView.vue` 负责请求、权限后的区块编排和刷新，不堆放所有图表配置。
- 图表数据转换和 ECharts option 构建拆成纯函数，便于单元测试。
- 通用卡片壳统一处理标题、说明、加载、空数据、失败重试和更新时间。
- 跳转统一由首页组装查询参数；目标页面逐步支持读取筛选参数。
- 快捷入口复用现有路由和 Element Plus 图标，不复制菜单配置。

## 11. 后端模块建议

```text
server/src/dashboard/
├─ dashboard.controller.ts
├─ dashboard.service.ts
├─ dashboard.module.ts
├─ dashboard.types.ts
└─ dto/dashboard.dto.ts
```

- Dashboard 是只读聚合模块，不新增实体和数据表。
- Service 注入现有业务实体仓库，集中完成统计口径和权限分支。
- Controller 只处理参数、当前用户和响应，不编写聚合 SQL。
- 第一版预计无需数据库迁移；若 `EXPLAIN` 证明缺少关键索引，再单独增加迁移。

## 12. 视觉与响应式规范

- 延续深色科技蓝侧栏、`#f0f2f5` 内容背景和白色卡片。
- 顶栏已经显示“首页”，正文不再重复大标题；欢迎区使用姓名、摘要和更新时间。
- 卡片边框使用浅灰，阴影克制；不使用大面积彩色渐变背景。
- 数字主值建议 24～28px，卡片标题 14px，辅助信息 12～13px。
- 关键数字可点击时提供清晰 hover 和键盘聚焦态，整卡不默认伪装成按钮。
- 图表卡默认最小高度 320px；待办列表和健康概览可按内容自适应。

响应式建议：

| 内容区宽度 | 布局 |
| --- | --- |
| `>= 1440px` | 12 栅格；指标 6 列；主趋势 8 + 健康 4 |
| `1200～1439px` | 指标 3 列两行；主趋势 8 + 健康 4 |
| `768～1199px` | 指标 2 列；图表全部单列或 6 + 6 |
| `< 768px` | 指标单列；图表单列；弱化次要 Tooltip 内容 |

断点按主内容区实际宽度判断，不能只按浏览器宽度判断，因为左侧菜单会占用 64px 或 210px。

## 13. 状态与异常处理

每个区块必须分别具备：

- 首次加载骨架屏。
- 手动刷新中的轻量状态，保留旧数据避免整页闪烁。
- 无数据状态，例如“近 7 天暂无 Agent 执行”。
- 无权限时直接不渲染。
- 接口失败时显示“数据暂不可用”和重试，不显示 0。
- 返回未知业务状态时归入“未识别”，并在 Tooltip 中说明，不能猜测成成功。

全局刷新按钮建议增加 10 秒前端节流；切换 7/30 天只刷新趋势相关数据。页面不自动高频轮询，第一版可在用户回到页面且数据超过 5 分钟时静默刷新一次。

## 14. 实施阶段

### 第一阶段：核心可用版

- 新增 Dashboard 聚合接口及权限过滤。
- 替换硬编码首页。
- 上线六个核心指标、Agent 趋势、产品/SKU 分布、待办列表和快捷入口。
- 安装 ECharts 并建立通用图表卡片。

### 第二阶段：运营增强版

- 增加客服 AI 任务趋势、知识库健康环图、业务健康概览和最近动态。
- 完善所有指标下钻及目标页面查询参数回显。
- 根据真实数据量进行 SQL 与索引优化。

### 第三阶段：数据能力扩展

- 如果未来新增库存、订单或价格模型，再增加库存预警、销量和销售额图表。
- 如果新增客服状态事件表，再增加转人工率、平均等待和平均接待时长趋势。
- 根据使用反馈评估个人收藏、快捷入口排序和首页布局偏好，不预先实现拖拽系统。

## 15. 验收标准

- 首页不再存在写死的业务数字或脚手架说明。
- 任一展示指标均有明确数据库来源、时间范围和统计口径。
- SKU 统计明确是 SKU 记录数，不出现库存或销量歧义。
- 无权限用户无法从聚合接口获得对应区块数据。
- 单一区块失败不影响其他区块展示。
- 指标卡和待办可跳转到正确业务页面。
- ECharts 在侧边栏展开、收起和窗口变化后正常 resize，无重复实例或内存泄漏。
- 7 天与 30 天切换结果正确，日期按 `Asia/Shanghai` 计算。
- 所有图表具备加载、空、失败和未知状态。
- 桌面常见内容宽度下无横向滚动；窄屏按单列降级。
- 前后端类型检查、后端测试、前端构建和组件复用扫描通过。

## 16. 推荐结论

建议采用“**六项核心指标 + Agent 主趋势 + 产品/SKU 分布 + 客服趋势 + 知识健康 + 待办/快捷入口**”的方案。它比单纯待办首页更丰富，又能保证每个模块都有真实数据来源和明确操作去向。

第一阶段优先完成 Agent、产品/SKU 和待办三条主线；这三部分数据基础最明确，也最能体现当前平台区别于普通中后台模板的核心价值。客服历史转人工趋势、库存和销售相关指标需要额外事件或业务实体，放到后续数据能力完备后再做。
