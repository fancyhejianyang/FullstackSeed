# 手动解析实现原理

本文说明知识库的「手动解析」能力：它由本系统的后端直接读取文件并提取正文，不依赖第三方 MinerU 服务。适合内容结构相对简单、希望结果可控、或不希望把文件提交到外部解析服务的场景。

## 先区分三个阶段

知识库从文件到可被 AI 回答使用，要经过三个彼此独立的阶段：

```text
原始文件 / 文本
  ↓ 解析
可编辑的知识库正文
  ↓ 分片
多个可检索的内容片段
  ↓ 索引
全文索引与向量索引
  ↓
AI 聊天检索与回答
```

- **解析**：把文件变成正文。本文只讨论这一阶段。
- **分片**：按分片配置把已解析正文切成片段；手动分片可在详情页人工选择范围，自动分片读取默认分片配置。
- **索引**：为分片生成检索所需的全文与向量数据。

所以手动解析成功只表示「正文已经产生」，并不表示它已经能够被聊天应用检索；还需要完成分片和索引。

## 支持范围与处理方式

当前知识库页面支持的内容类型如下。

| 内容类型 | 手动解析方式 | 适用情况 |
| --- | --- | --- |
| 文本（TXT / Markdown / 直接输入） | 使用已保存的文本正文 | 已经是可读文本时最快、最稳定 |
| Word（`.doc` / `.docx`） | 提取正文和可识别的超链接文本 | 普通制度、通知、说明文档 |
| PDF | 先提取 PDF 内嵌文本；未提取到文本时，将页面转为图片后使用本地 OCR | 有文本层的 PDF，或页数可控的扫描 PDF |
| 图片 | 使用本地 OCR 识别图片中的文字 | 截图、扫描图片、海报等 |

> 当前系统的知识库内容类型以文本、Word、PDF、图片为准。不要因为某个外部服务声称支持 PPT、表格等格式，就假定它们已被当前知识库上传和解析流程完整支持。

## 实际流程

```text
上传文件或录入文本
  ↓
知识库保存文件地址、文件名或正文
  ↓
选择「手动解析」
  ↓
后端读取文件（或直接使用文本正文）
  ↓
按内容类型调用系统内置解析器
  ↓
标准化为知识库正文并保存
  ↓
状态变为“已解析，等待分片”
```

对于 PDF，流程还有一层优先级：

```text
PDF
  ↓
提取内嵌文本
  ├─ 提取到正文：直接保存
  └─ 没有正文：渲染为页面图片 → 本地 OCR → 保存识别结果
```

这意味着：带文字层的普通 PDF 不会无条件执行 OCR；只有没有可提取文本的扫描型 PDF 才会进入本地 OCR 兜底。这样通常更快，也能避免 OCR 对原有文字造成不必要的识别误差。

## 手动解析的结果

解析完成后，系统会：

- 保存标准化后的正文到知识库文档；
- 保留文档的来源名称、关键词、口语描述和匹配优先级等检索辅助信息；
- 清除该文档旧的分片，避免新旧正文混用；
- 将知识库状态置为「等待分片」。

管理员应在正文页抽查标题、编号、表格转写和关键字段；确认正文正确后，再执行自动分片或人工分片，最后执行索引。

## 何时优先用手动解析

| 场景 | 建议 |
| --- | --- |
| TXT、Markdown、可直接复制的制度文本 | 优先手动解析 |
| 有文字层、版式简单的 PDF | 优先手动解析 |
| 普通 `.doc` / `.docx` 通知或说明 | 优先手动解析后抽查 |
| 对数据外发、成本或解析确定性敏感 | 优先手动解析 |
| 扫描件、复杂表格、公式、图文混排且手动结果不理想 | 改用 AI 模型解析 / MinerU 解析 |

## 常见问题与处理

| 现象 | 常见原因 | 建议处理 |
| --- | --- | --- |
| 提示无法读取文件 | 文件地址失效，或后端无法访问存储文件 | 检查上传文件是否存在、存储配置和文件访问权限 |
| PDF 解析后为空 | PDF 没有文字层，且本地 OCR 未识别出文字 | 检查扫描清晰度、OCR 语言资源和页数限制；必要时改用 MinerU |
| Word 结果缺少复杂表格或版式 | Word 正文提取以可检索文本为目标，不等同于还原原始排版 | 抽查关键表格；需要保留复杂布局时使用 MinerU 并核对结果 |
| 图片识别失败或乱码 | 图片模糊、倾斜、分辨率低，或本地 OCR 语言资源不完整 | 使用更清晰的原图，确认 OCR 语言配置，或改用 AI 模型解析 |
| 解析完成但聊天仍找不到内容 | 尚未分片或索引，或检索配置未覆盖该知识库 | 依次检查处理阶段、分片数量、索引状态和检索配置范围 |

## 与 MinerU 的关系

手动解析与 MinerU 解析是两条可选的**解析**路径：前者由系统本地完成，后者将可访问文件交给外部服务完成。两者都以「得到可检索正文」为结束点，之后仍进入同一套分片与索引流程。

页面中的「MinerU 分片」是自动分片入口的名称，它处理的是已经保存的正文，不是再次调用 MinerU 读取原始文件。若问题是原文少页、表格错乱或正文为空，应优先排查解析；若正文完整但回答没有带出相关段落，才应排查分片、索引和检索策略。
