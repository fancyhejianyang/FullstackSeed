# 知识库解析（手动 + MinerU）

本文说明知识库文件如何变成可供 AI 聊天检索的内容，并帮助管理员选择手动解析或 MinerU 解析。它描述的是产品能力和排查思路，不要求了解后端实现细节。

## 先理解完整链路

```text
原始文件 / 文本
  ↓ 解析：得到可编辑正文
知识库文档正文
  ↓ 分片：切成可检索片段
知识库分片
  ↓ 索引：建立全文与向量数据
AI 聊天可以检索并回答
```

三个阶段相互独立：

- **解析**解决「原文件内容能否完整读出来」。
- **分片**解决「长正文怎样切成适合召回的片段」。
- **索引和检索配置**解决「聊天时能否找到正确片段」。

因此，解析完成只表示已经有正文；仍需分片和索引。若正文页已经完整而聊天漏答，不应先重跑解析。

## 两种解析方式如何选择

| 对比项 | 手动解析 | MinerU 解析 |
| --- | --- | --- |
| 执行位置 | 系统本地解析 | 第三方服务解析 |
| 适合资料 | 纯文本、普通 Word、文字层完整的 PDF | 扫描 PDF、图文混排、复杂表格、公式、版式复杂的文档 |
| 结果特点 | 快、可控、成本低，以提取可检索文本为目标 | 通常返回 Markdown，较擅长保留标题、列表、表格等结构 |
| 前置条件 | 后端能读取文件；本地 OCR 可用 | MinerU 与 AI 功能配置正确启用，且 MinerU 能读取文件地址 |
| 不适合时 | OCR 对模糊扫描件或复杂布局可能不够理想 | 不适合对外发、成本或服务等待时间敏感的简单文本 |

建议优先用手动解析；只有手动结果不完整，或资料明显依赖版式结构时，再使用 MinerU。

## 手动解析做了什么

当前知识库支持文本、Word、PDF 和图片。

| 类型 | 处理方式 |
| --- | --- |
| 文本（TXT / Markdown / 直接输入） | 直接使用保存的正文 |
| Word（`.doc` / `.docx`） | 提取正文和可识别的超链接文本 |
| PDF | 先读取 PDF 内嵌文字；只有未读到文字时才将页面转图片并走本地 OCR |
| 图片 | 使用本地 OCR 识别文字 |

PDF 的处理顺序尤其重要：有文字层的 PDF 会直接提取文本，不会无条件 OCR；扫描型 PDF 才使用本地 OCR 兜底。这样既更快，也能避免 OCR 重识别导致的错字。

手动解析完成后，系统会保存标准化正文、清除旧分片，并将处理状态置为「已解析，等待分片」。管理员应先在正文页抽查标题、编号、关键条款和表格，再继续分片与索引。

## MinerU 解析如何工作

在知识库列表选择「AI 模型解析」时，如果 OCR 或文档解析功能配置已启用 MinerU，且知识库有非文本文件地址，系统会优先将文件交给 MinerU。文档详情页也可直接选择「MinerU 解析」重新处理已有文档。

```text
选择 AI 模型解析 / MinerU 解析
  ↓
校验 AI 功能配置、MinerU 配置和文件地址
  ↓
将私有文件转换为临时可读取地址（需要时）
  ↓
创建 MinerU 任务并记录任务 ID
  ↓
后台轮询任务进度
  ↓
读取 Markdown 或结果包中的正文
  ↓
保存正文、清除旧分片，等待重新分片和索引
```

要让 MinerU 生效，需要：

1. 配置可用的 MinerU 服务地址、令牌、模型版本、轮询间隔和超时时间；
2. 在 OCR 或文档解析的 AI 功能配置中启用 MinerU，并绑定对应 MinerU 配置；
3. 确保解析期间原文件仍存在，且 MinerU 能访问其 URL；私有对象存储必须使用有效期足够的签名 URL；
4. 按需要开启 OCR、表格或公式识别。

任务会显示处理中、进度或失败原因。服务重启后，已记录任务 ID 的处理中任务会继续查询，避免直接丢失结果。

> 当前系统知识库的主要内容类型仍是文本、Word、PDF、图片。不要仅因 MinerU 服务本身支持更多格式，就假定所有格式已被当前上传和知识库流程完整支持。

## 解析后必须做的四步

1. **核对正文**：抽查页数、标题、表格、公式与关键条款是否齐全。
2. **执行分片**：自动分片读取默认分片配置；也可以在详情页人工框选分片。
3. **执行索引**：生成全文与向量检索数据。
4. **验证聊天**：确认聊天应用绑定的检索配置覆盖该知识库，再进行问答测试。

页面中的「MinerU 分片」是自动分片入口的名称：它读取**已经保存的正文**和默认分片配置（分片长度、重叠、按段落/长度、标题保留），不会再次把原始文件交给 MinerU 提取内容。修改分片参数后，应重新分片并重新索引。

## 按现象快速定位问题

| 现象 | 应检查的阶段 | 常见处理 |
| --- | --- | --- |
| PDF/图片正文为空或缺页 | 解析 | 检查文件质量、可访问性和本地 OCR；必要时改用 MinerU |
| Word 缺少复杂表格或排版 | 解析 | 手动解析以可检索文本为目标；必要时改用 MinerU，并抽查结果 |
| MinerU 创建任务失败 | MinerU 配置 | 检查服务地址、令牌、AI 功能配置绑定和文件 URL |
| MinerU 长时间处理中或超时 | MinerU 任务 | 检查服务端进度、文件大小、签名 URL 有效期和超时时间 |
| MinerU 成功但正文为空 | 解析结果 | 查看失败信息或结果包；更换清晰原件，必要时手动补充正文 |
| 正文完整，但聊天没有回答后半部分 | 分片、索引、检索 | 检查分片大小/重叠、索引状态、召回上限、最低相关度和重排 |
| 聊天完全找不到某份已处理文档 | 索引、检索配置 | 确认已分片且已索引，并确认聊天的检索范围包含该知识库 |

## 最终判断原则

- **正文少了、错了、结构乱了**：优先处理解析，先尝试手动解析，复杂资料再用 MinerU。
- **正文正确，聊天回答不完整或命中错误**：不要重跑 MinerU；优先检查分片、索引和检索配置。
- **文件简单**：手动解析优先。
- **文件复杂、扫描件或版式敏感**：MinerU 优先，并在解析完成后人工抽查关键内容。
