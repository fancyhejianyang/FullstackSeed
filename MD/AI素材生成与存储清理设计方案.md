# AI 素材生成与存储清理设计方案

> 状态：待确认方案，未实现业务代码。日期：2026-10-19。
>
> 目标：通过提示词和风格生成图片，重新生成成功后替换当前素材；文件使用独立存储路径，可安全清理废弃结果，不影响文章封面、知识库附件等现有文件。

## 1. 建议结论

新增“内容创作 → 素材生成”，首期只做单张图片：填写提示词、选择风格和生图配置，生成后预览、下载、重新生成或删除。风格先提供受控预设，不增加分类、标签、复杂模板管理或批量计费生成。

“覆盖”应当覆盖素材记录的当前结果，不原地覆盖同一个 OSS 文件：先生成并保存新文件，成功后切换记录指向，再把无引用的旧文件加入延迟清理。失败时旧图仍可使用。

沿用现有 OSS 账号和域名，在同一个 Bucket 内分配独立前缀即可起步；不修改全局 `uploadDir`，不要求立即创建新 Bucket。新增文件登记与清理能力可供后续 [ComfyUI 接入](./ComfyUI本机工作流接入设计方案.md)复用，两者不共用文章生成任务表，也不调用 Agent。

## 2. 当前项目已经具备什么

| 当前能力            | 代码位置                                                              | 复用方式和限制                                                                                                                                          |
| ------------------- | --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| AI 模型账号         | `server/src/knowledge-ai-providers/`                                  | 已分 `textModels`、`visionModels`、`imageGenerationModels`，有独立生图 URL 和 `openai/dashscope` 协议；素材必须使用生图目录，不能使用识图或文本目录兜底 |

| 持久化异步任务      | `server/src/content-articles/content-generation.service.ts`           | 可参考请求幂等、条件抢占、版本绑定、租约和不自动重复计费规则；文章服务的 120 秒期限不是所有媒体任务的通用限制                                           |

| 界面与权限          | `web/src/views/content-article/`、`web/src/components/`               | 复用 Table、Form、Dialog、Button 和图片预览，列表不返回长提示词、快照或完整供应商响应                                                                   |

本地保存的存储配置已启用阿里云 OSS，`uploadDir=uploads`，Bucket、公开域名和凭据字段已填写。这只说明本地配置状态，不代表已验证线上账号权限、CDN 域名回源、Bucket 版本控制或生命周期规则。

现有 OSS 上传键为 `uploadDir/年/月/日/UUID.ext`；本地上传为 `uploads/年/月/日/UUID.ext`，本地分支目前没有使用 `uploadDir`。`UploadResult` 只返回 URL、文件名、类型和大小，没有可靠的对象键、存储位置登记、引用关系或物理删除机制。

另外，存储配置页仍有“未接云 SDK 时回退本地”的旧提示，与当前 OSS 实现不一致。实现本方案时应同步纠正说明，不以这段界面文案判断真实存储能力。

## 3. 页面和配置

### 3.1 素材页面

编辑区只保留三个主要输入：

- 提示词：必填，描述主体、场景和构图。
- 风格：原始描述、写实摄影、水彩、扁平插画、电影质感等受控预设；可选“自定义风格”后填写一段文字。
- 生图配置：记住上次选择，必须是启用且可用的图片生成功能配置。

不强制填写标题。列表显示 40×40 缩略图、提示词单行摘要、风格、状态、更新时间；完整描述、实际参数和错误放在详情。操作为查看、编辑、生成或重新生成、下载、删除，不再设计“采纳标题/正文”等文章操作。

关闭页面不取消后台任务；重新进入读取最新状态。重新生成期间仍展示旧图，旁边显示本次生成状态。成功后自动替换；失败显示原因，旧图不消失。活跃任务禁止重复生成，删除活跃素材首期直接阻止并提示稍后处理。

风格是提示词片段，不等于真实更换模型、LoRA 或画风权重。首期使用代码注册的预设加版本号，服务端组合“配置默认画面要求 + 用户提示词 + 风格要求”，不通过字符串执行代码。记录最终提示词快照；不默默增加一次文本模型润色调用。

### 3.2 AI 功能配置

建议在现有“AI 功能配置”增加 `imageGeneration` 类型：账号、该账号生图模型、默认画面要求。生图不展示温度、Think、Markdown/纯文本格式或客服工作流。

现有 `AiFeatureConfig` 的 `providerId/model/systemPrompt` 可复用，其中 `systemPrompt` 在该类型下表示画面默认要求，只拼接为生图提示词，不调用聊天接口；旧类型含义不变。仅在需要可配置尺寸时增加严格校验的 `imageParameters` 字段，不接受自由请求 JSON。

必须同步调整后端类型常量、DTO、配置规范化与执行校验、模型目录选择，以及前端类型、表单和模型选项。当前 `getFeatureModels()` 默认返回文本目录，新增类型不能仅增加一个下拉选项，否则仍可能选错模型。

执行时使用已有 `resolveMediaTarget(providerId, model, 'imageGeneration')`，由后端再次验证账号启用、密钥、模型归属及完整端点。新增素材专用只读配置选项接口，只返回配置名称、ID 和模型，不借此授予第三方配置读取权限或泄露凭据。

首期沿用已实现协议：OpenAI 兼容路径固定单张 1024×1024，DashScope 使用已实现的单图请求及模型默认尺寸。只有某个协议、模型的参数经过验证后，才显示它支持的尺寸或负向提示词；不凭模型名称推测能力。缺配置时阻止提交，不能像文章可选封面一样静默跳过整个功能。

## 4. 独立存储路径

### 4.1 目录不是另一个 CDN 服务

OSS 保存实际对象，CDN 缓存并分发公开 URL。功能隔离首先是 OSS 对象键隔离，并保持 CDN 路径映射一致，不是创建一个“CDN 文件夹”。

建议在现有上传根路径下增加固定业务范围，环境名由部署配置决定，不允许普通请求指定：

```text
uploads/
  原有 年/月/日/文件                         # 不迁移、不参与新清理
  ai-materials/
    prod/
      objects/{userId}/{materialId}/{revision}/{fileId}.png
      staging/{taskId}/{fileId}.part          # 临时中转，可选
      published/{userId}/{exportId}/{fileId}.png
    dev/
  comfyui/
    prod/outputs/{userId}/{taskId}/{fileId}.mp4
```

`uploads` 是当前 `uploadDir` 的示例；`ai-materials` 与 `comfyui` 是服务端注册的 scope。日期可以用于管理，但不能用日期作为可删除与否的唯一依据。这里的用户 ID 只用于组织文件，不是授权机制；公开链接本身不提供用户隔离。

CDN 如无特殊回源改写，可直接复用现有域名拼接对象键；实际域名若有路径改写，应验证完整 URL 与对象键的对应关系。公开域名不能作为文件身份。

### 4.2 存储接口兼容扩展

给现有上传能力增加受控上下文，或新增 `ManagedFilesService` 包装上传实现：

```ts
// 拟议服务端契约，不是允许浏览器指定任意路径的 DTO。
saveManagedFile(file, {
  scope: "ai-materials",
  ownerId,
  businessId: materialId,
  taskId,
  revision,
});
// 返回 fileId、url、objectKey、provider、storageLocationId、mimeType、size。
```

普通 `/uploads` 的入参和 URL 回显契约不变；只有新模块进入受管存储。不要把通用上传接口改成允许前端传任意 `uploadDir`、Bucket 或完整对象键。

本地分支同样支持业务 scope，解析后的实际路径必须位于专用根目录内，并拒绝 `..`、绝对路径、跨盘、符号链接逃逸。新增本地专用路径不改变旧文件 URL。

文件登记保存实际 `provider`、Bucket/端点或本地根标识、`objectKey`、存储位置版本，以及可用的 OSS 对象版本 ID；不能在删除时从 URL 猜 key，也不能用“当前配置”删除过去 Bucket 的文件。秘密只保存在受控凭据配置中，文件记录仅保存凭据引用。

当前存储是单份 JSON 配置，不具备历史连接档案。首期至少记录不可变位置指纹：若当前配置与文件位置不匹配，停止清理并标记需管理员恢复对应连接，不能向新 Bucket 盲删。需要支持频繁换 Bucket 时，再增加可管理的存储连接档案，不为本功能先重写所有存储配置。

## 5. 覆盖和文件生命周期

### 5.1 生成成功才切换

```text
保存提示词与风格
  → 创建绑定素材版本的任务
  → 调用指定生图模型
  → 校验并保存新文件，登记为待挂接
  → 数据库事务切换 currentFileId，任务置成功
  → 旧文件失去有效引用后进入延迟清理
```

同一个素材的 `id` 不变，每次生成使用新的任务 ID、递增生成序号和唯一文件键。业务版本校验、任务抢占和唯一活跃素材约束共同阻止迟到结果覆盖新的编辑或新任务。

事务前确认素材仍存在、版本一致、任务仍归当前 worker。若不满足，新文件只进入清理候选，不修改当前图。上传成功但数据库提交失败也必须能找到孤儿文件：先登记预计对象键，再上传；上传流程中断后由清理扫描对账。

新地址解决同名缓存问题，优于依赖每次刷新 CDN。阿里云也建议用文件版本或哈希命名规避源站同名更新后的缓存不一致。[CDN 缓存处理文档](https://www.alibabacloud.com/help/en/cdn/user-guide/cache-troubleshooting)

### 5.2 可删条件

只有同时符合以下条件才允许物理删除：

1. 属于登记过的新业务 scope、环境和已确认的存储位置。
2. 不是任何素材的当前结果，也没有有效业务引用或保留标记。
3. 没有执行中任务、待完成上传或输出归档依赖它。
4. 已达到延迟清理时间，且删除前再次校验引用与状态。

“没有引用”需以登记关系判断，不能只依赖可漂移的 `refCount`。建立引用与领取删除任务采用同一文件行锁/条件更新规则：进入 `deleting` 后禁止新增引用，避免检查完成后被重新使用的竞态。

建议旧图无引用后保留 24 小时，上传孤儿保留至少 24 小时；作为可调默认值，不作为 OSS 已配置事实。当前有效图不按年龄自动过期。清理失败独立重试，不能触发重新生图。

### 5.3 引用和正式发布

现有文章封面等业务只存 URL，没有全站引用台账。因此本次清理只覆盖新登记素材，不扫描或删除历史上传，也不能默认认定某个旧 URL 无人使用。

首期可直接下载素材文件；不承诺“当前生成图 URL”是永久发布链接。需要给文章或其他业务复用时，必须通过受控选择接口登记引用；尚未适配引用登记的旧模块，先将素材复制到 `published/` 下并登记为保留版本，再返回正式链接。不能把临时版本 URL 直接放进正文后继续按垃圾删除。

重新生成不会篡改已被其他文章引用的旧图。外部平台使用链接后无法从数据库反推引用，因此正式发布副本不参加自动清理，只能显式删除，并提示外部链接可能失效。

### 5.4 OSS 清理和 CDN 失效是两件事

在“第三方配置 → OSS/CDN”增加折叠的“业务文件与清理”区：按 scope 统计当前文件、无引用文件、待删除、删除失败的数量和体积；先预览清单，再确认清理。普通用户只清理自己的素材；跨用户清理由独立 `MediaStorage.read/update` 权限控制，不从 `StorageConfig.read` 自动继承。

清理以文件登记列表为目标，通过精确对象键逐个或有界批量删除；默认不提供“输入路径后整目录删除”。本地也是逐文件删除，不递归删除整个 `uploads`。

云端权限应限制在对应业务前缀，分别授予需要的上传、读取和删除能力；对象列举仅用于有界对账，不申请整个账号的管理权限。现有账号能上传不代表能删除，接入前用专用测试对象核验；删除权限不足只记录清理失败，不影响当前素材使用。

OSS 生命周期可以按前缀/标签处理对象，但不理解数据库引用。不能给整个 `ai-materials/` 配置“若干天后删除”，否则有效图片也会消失。仅对明确的临时中转前缀使用生命周期兜底，正式文件以应用引用清理为准。[OSS 生命周期元素](https://www.alibabacloud.com/help/en/oss/user-guide/configuration-elements)

如果 Bucket 开启版本控制，删除当前键可能留下历史版本或删除标记；需要按实际版本控制状态设计旧版本清理，不宣称逻辑删除就释放全部空间。[OSS 生命周期操作说明](https://www.alibabacloud.com/help/en/oss/user-guide/configuration-elements)

删除源文件不等于 CDN、浏览器缓存立即失效。常规重新生成依靠新 URL，无需等待刷新；如果要求旧链接尽快不可访问，应另行接入 CDN URL 刷新并记录状态，刷新权限和服务能力独立配置，首期可由管理员在云控制台操作。不能承诺已被下载或转载的文件可回收。

## 6. 数据与接口草案

以下为拟新增字段，前后端统一 camelCase；列表分页沿用 `{list,total}`，长 JSON 仅在详情返回。

| 实体与表名                                             | 核心字段                                                                                                                                                  | 用途                                                                                            |
| ------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `AiMaterial` / `ai_materials`                          | `userId, prompt, styleKey, customStyle, aiConfigId, currentFileId, version, generationRevision`                                                           | 用户只编辑提示词、风格和配置；技术字段不增加表单负担                                            |
| `MaterialGenerationTask` / `material_generation_tasks` | `userId, materialId, materialVersion, requestId, status, snapshot, resultFileId, workerId, leaseExpiresAt, startedAt, finishedAt, errorMessage`           | 快照含实际模型、风格版本、最终提示词，不含密钥；`userId+requestId` 唯一，同素材至多一个活跃任务 |
| `ManagedFile` / `managed_files`                        | `ownerId, scope, environment, storageLocationId, storageIdentity, objectKey, objectVersionId, mimeType, size, status, deleteAfter, retryAt, errorMessage` | 文件身份、归档与删除状态；状态拟为 `staged/ready/pending_delete/deleting/deleted/delete_failed` |
| `ManagedFileReference` / `managed_file_references`     | `fileId, ownerId, businessType, businessId, role`                                                                                                         | 当前素材、输出任务或正式发布的有效引用，按业务引用唯一约束                                      |

任务状态拟为 `pending/running/storing/succeeded/failed/interrupted/unknown`。`unknown` 表示上游是否已执行无法确认，不能自动重试计费请求；用户核实后才可明确放弃并发起新任务。历史任务仅存执行摘要及已清理文件状态，不因保留任务日志而永久保留被替换的素材文件。

拟议路由：

| 路由                                         | 用途与权限                                                        |
| -------------------------------------------- | ----------------------------------------------------------------- |
| `GET/POST /api/ai-materials`                 | 本人分页 / 新建；`AiMaterial.read/create`                         |
| `GET/PATCH/DELETE /api/ai-materials/:id`     | 本人详情 / 版本校验编辑 / 软删；`AiMaterial.read/update/delete`   |
| `POST /api/ai-materials/:id/generate`        | `{version, requestId}`，创建新任务并快速返回；`AiMaterial.update` |
| `GET /api/ai-materials/config-options`       | 无凭据生图配置选项；`AiMaterial.read`                             |
| `GET /api/material-generation-tasks`、`/:id` | 本人执行摘要 / 详情；`AiMaterial.read`                            |
| `POST /api/ai-materials/batch-delete`        | 有界批量软删，活跃素材拒绝；`AiMaterial.batchDelete`              |
| `GET /api/media-storage/cleanup-preview`     | 管理员读取确定范围的候选清单；`MediaStorage.read`                 |
| `POST /api/media-storage/cleanup`            | 绑定预览条件和候选版本执行，清理前重查；`MediaStorage.update`     |

真实下载、预览和配置选项均做归属校验；公开素材本身不适合私密信息。若未来要支持私有素材，应改成私有桶签名访问或鉴权代理，不能把难猜 URL 当访问控制。

## 7. 实施拆分

### 第一步 建立受管文件范围

新增 `server/src/managed-files/`，复用现有本地/阿里云 SDK 上传，不替换所有旧上传调用。增加固定 scope、文件登记、引用、精确删除、清理预览与失败重试；存储配置变更不匹配时保守停止。

同时补齐跨环境路径隔离、对象键校验、原有 `saveFile()` 兼容测试。不要自动改云端生命周期、Bucket 权限或 CDN 刷新策略。

### 第二步 建立素材生成闭环

从 `server/src/demo/` 与 `web/src/views/demo/` 复制模块基础，新增 `ai-materials`、任务与 `web/src/api/aiMaterial.ts`。扩展 AI 功能配置类型和服务选项，复用公共图片协议；增加请求幂等和版本绑定，完成“生成成功切换、失败保留”。

不增加 Redis/BullMQ 依赖：先沿用 MySQL 持久任务和条件抢占。限制用户并发及每账号并发，状态查询只读。后续规模证明有必要时再引入专业队列。

### 第三步 接入菜单与验收

在内容创作分组加入素材生成入口，补用户权限 seed、动态菜单分组可见性及前端分组首个可用页面重定向。风格管理和图片参数扩展暂不新增菜单。

同步 `.design-spec.md`、组件契约（仅扩展公共组件时）、迁移和 CHANGELOG。不要修改文章的生成、采纳、公开封面与历史数据行为。

## 8. 验收清单

- 提示词、风格与实际生图模型匹配；新增类型不会落入聊天模型目录。
- 连续双击、请求响应丢失不会创建两份内部任务；调用结果不确定不自动再次计费。
- 新图成功才覆盖，失败、保存失败、版本冲突或迟到响应不会清掉旧图。
- 新旧 URL 不同；列表不依赖 CDN 刷新才能显示新图。
- 文章封面、知识库及其他旧上传不参与新模块清理。
- 当前引用、正式发布、活跃任务与其他环境文件均受保护；并发新增引用和清理不会互相绕过。
- 上传后崩溃、数据库失败、Bucket 切换、删除权限不足都能对账和重试，不丢清理凭据定位。
- 版本控制和生命周期在测试 Bucket 验证后再配置；清理预览与实际删除范围一致。
- 前后端类型、静态检查、单元测试及迁移验证；真实生图和云端删除必须使用明确的测试数据与专用前缀。

## 9. 首期范围

建议直接做：提示词与风格、单图异步生成、成功覆盖、独立路径、文件登记、延迟清理、清理预览、生成状态。

后续再做：自定义风格管理、批量生成、图生图、供应商异步协议、自动 CDN 刷新、多个独立存储账号，以及与旧业务的素材选择器整合。

该方案优先解决“能生成、不会误覆盖、垃圾文件可定位和可清理”。ComfyUI 的视频与工作流调度另见第二份方案，不把它塞入当前云端单图接口。
