# Agent 业务模块统一接入

## 本次能力

“默认可以接入”指模块的执行器、查询卡片和录入草稿已经接通，管理员可在 Agent 应用中选用；不等于给所有应用或员工自动授权。

| 模块 | 工具前缀 | 查询列表 / 详情 | 确认后新增 | 特殊边界 |
| --- | --- | --- | --- | --- |
| 示例数据 | `demo` | 支持 | 支持 | 复用 Demo DTO 和业务服务 |
| 产品 | `product` | 支持 | 支持 | 产品编码必填并保持原唯一性规则 |
| SKU | `productSku` | 支持 | 支持 | 需要读取所属产品的权限，保留已有 SKU 编码与幂等逻辑 |
| 标准问答 | `standardQa` | 支持 | 支持 | 强制保存为 draft，不能直接发布或跳过审批 |
| 口语词库 | `colloquialTerm` | 支持 | 支持 | 默认停用，可在确认前编辑启用状态 |
| 文本知识库 | `knowledgeBase` | 支持 | 支持 | 默认停用，使用已有分类和文本拆分规则；不启动文件下载、解析、分片、索引任务 |
| 知识库分类 | `knowledgeCategory` | 支持 | 支持 | 上级可选、留空为顶级；父分类必须真实存在，不能移动/删除分类 |

每个模块开放 `list / detail / create` 三个工具，七类共 21 个；同时保留原 `product.query` 产品/SKU 聚合查询。

不开放修改既有数据、删除、批量操作、发布、审批、账号、角色、权限、密钥、系统配置。工具目录中的 `update/delete/batchDelete` 仍只是契约，不进入 Agent 执行器。

## 如何启用

1. 本次模型调度新增 `agent_apps.modelRouting` 可空 JSON 文本列。生产环境先备份、审阅待执行迁移，在 `server/` 执行 `npm run migration:run`（会运行所有待执行迁移），再部署/重启后端；开发环境使用既有 synchronize 时重启同步。迁移 `1792166400000-AddAgentModelRouting.ts` 不回填/改变旧应用授权，旧应用仍按优先顺序调度。后端启动时补齐分类指令目录。本次开发未操作实际数据库或启动服务。
2. 打开「Agent 管理 → Agent 应用管理」，编辑目标应用，在「业务工具」选择所需列表、详情、创建工具。
3. 需要录入时显式开启「写入总开关」。员工必须有 `AgentWorkspace.read`、应用使用权限及对应业务的 `Module.read/create` 权限；SKU 新增还需要 `Product.read`，知识库/分类新增还需要 `KnowledgeBase.read` 供分类选择。
4. 配好模型账号、模型列表、调度策略和职责。模型阶段尝试上限与单轮业务工具上限独立：识别/规划/回答不消耗业务次数；实际查询和准备草稿仍计数。默认模型上限 8 次，业务工具 5 次，总超时 60 秒。
5. 在工作台说明业务模块和请求，核对查询结果或草稿。自然语言“可以入库”只展示真实草稿；必须点击“确认录入”才提交。

建议分别选择列表、详情和创建，既能查重，也能从真实结果中识别记录 ID。只有创建权限而没有读取权限时，不会自动获得相关查询能力。

## 图片识别与图片生成（2026-10-16）

工作台已支持实际上传识图和同步文生图，不仅是配置项。图片能力与业务写入、文本模型调度分开授权：识图不会自动入库；生成图片不修改业务数据。

### 配置顺序

1. 生产先备份数据库并审阅待执行迁移，在 `server/` 执行 `npm run migration:run`，再更新前后端。新迁移为 `1792170000000-AddAgentMediaModelReferences.ts`；命令会运行所有待执行迁移。本次开发没有连接真实数据库、运行迁移或启动服务。
2. 「大模型账号 → 编辑」：
   - **视觉识别模型**：每行 `模型编码#显示名称`，填账号实际开通且支持 Chat Completions `image_url` 输入的模型。
   - **生图模型**：独立登记图片生成模型，不将视觉识别模型直接当成生图模型。
   - **生图协议**：选择 OpenAI Images 兼容接口，或阿里云 DashScope 同步多模态生图。
   - **生图接口地址**：填写完整 HTTPS 生成端点，不是聊天 API 路径，不带密钥或查询参数；使用本账号已保存的密钥。阿里云须核对地域/业务空间；`.maas.aliyuncs.com` 地址沿用现有 WorkspaceId 替换逻辑。
3. 「Agent 应用 → 编辑」：先选择 **模型账号**，再分别选择 **图片识别模型**、**图片生成模型**。两个下拉只展示该账号对应能力目录中的模型，与文本模型组分开配置；留空表示不开放该能力。生图未配置接口地址时无生图候选。手动切换账号会清空旧媒体引用，打开编辑回显不会清空；历史失效/跨账号引用显示禁用提示，须清除或重选。保存、上传与实际调用均核对账号归属；实际调用再次核对启用状态、密钥和对应模型目录。
4. 工作台不再手动选择模式：在输入框粘贴一张 PNG/JPEG/WebP，或点“添加图片”上传，确认预览后描述问题并发送。只有图片直接发送时补上“请识别并描述这张图片的内容”。要生图直接说“帮我画一只蓝色的小猫”等明确请求，由后台识别。图片随对应消息私有保存，支持历史回显与放大。粘贴不自动发送，也不会覆盖已有待发送附件；多图提示逐张发送，普通文字粘贴保持原行为。

开启任一媒体能力的应用（或带图请求）先用已授权文本模型进行结构化意图识别，独立于 priority/balanced/intent 策略；没有媒体配置且没有图片的旧应用保持原链。识别结果只有对话/业务、识图、文生图、参考图编辑、待澄清五种分流；同时识别业务意图及复杂度供后续文本调度复用，不再重复分类。生图描述可结合最近对话补全，但询问方法、否定/取消、只写提示词不应触发生图。分类失败不猜测执行；有歧义、缺图、参考图编辑需求时显示“待补充”，不伪称执行失败或生成成功。识别依赖模型，仍需用实际模型验收不同表达。

识图按本轮附件和问题调用；不是图片编辑、多图对比或自主多步工具循环。带附件的生图需求不会静默丢弃图片，当前提示尚未接通参考图编辑。识图后的文字结果可作为后续对话参考，业务录入仍走已有权限、草稿和确认流程。

### 接口协议与请求边界

| 能力 | 请求契约 | 实际结果 |
| --- | --- | --- |
| 识图 | 账号原 Chat Completions 地址，`messages[].content` 同时包含 `text` 和 Base64 `image_url` | 返回识别文字，不宣称执行过业务查询或写入 |
| OpenAI Images 兼容生图 | 管理员配置的完整 `/v1/images/generations` 地址；`model/prompt/n:1/size:1024x1024` | 解析 `data[0].b64_json` 或 `data[0].url`，保存真实图片 |
| DashScope 同步生图 | 完整 `/api/v1/services/aigc/multimodal-generation/generation` 地址；`model/input.messages/parameters.n:1` | 解析 `output.choices[0].message.content[0].image`，下载后私有保存 |

生图模型必须支持所选协议与本轮参数。DashScope 使用模型默认尺寸；本次不接异步任务查询、视频、图生图或编辑接口，收到任务 ID 而非图片时会明确失败。不能以模型回答中自称“已生图”或任意 Markdown 图片链接作为成功凭据。

协议按 [OpenAI Images API](https://developers.openai.com/api/reference/resources/images/methods/generate)、[OpenAI 图片输入指南](https://developers.openai.com/api/docs/guides/images-vision) 和 [百炼同步文生图 API](https://help.aliyun.com/zh/model-studio/qwen-image-api) 核对；不硬编码或自动推荐供应商模型名称。

### 选择图片模型时的真实能力测试

在 Agent 应用编辑页手动选择「图片识别模型 / 图片生成模型」后自动测试；**打开已有应用、回填历史值、刷新候选不会自动发起付费测试**。模型字段下显示测试结果，紧邻字段的「图片模型测试」区可重新测试或刷新候选。两种能力分开判断，不根据模型名字推断。

- 识图：以现有 Chat Completions 图片协议发送服务端生成的随机四色块 PNG，要求返回实际颜色顺序，并限制回答 `max_tokens: 256`。只有内容与图片匹配才通过；单纯回复 OK、HTTP 200 或自称有视觉能力不算通过。回答格式/内容不匹配只表示“无法确认”，不证明它一定是文本模型。
- 生图：按账号保存的协议发送单张请求。OpenAI Images 兼容使用 `model/prompt/n:1/size:1024x1024`；DashScope 同步使用 `model/input.messages/parameters.n:1`，保留模型默认尺寸。与工作台复用同一请求体构造和图片解析/下载安全校验。必须拿到真实图片字节且通过格式/大小校验；异步任务 ID、Markdown 链接或文字“生成成功”不算通过。测试图只在内存校验，不保存到会话、数据库或公开目录。
- 明确无效：供应商明确返回模型 ID 不存在/无效，或明确不支持此次图片能力，清空该字段并隐藏当前编辑窗口中的对应候选，展示原因。**不删除账号目录、不修改其他应用**；返回「大模型账号 → 编辑」修正目录后，点「刷新模型候选」重新获取并选择。
- 无法确认：鉴权失败、权限不足、余额/额度异常、429 限流、服务故障、超时、网络或接口参数不匹配，均保留候选并提示检查。HTTP 400/404 本身不等于模型无效，尤其不能把错误的接口地址/尺寸配置误判为非图片模型。
- 新接口 `POST /agent-apps/probe-media-model` 接收 `{providerId, model, kind: 'vision' | 'imageGeneration'}`，返回同一引用及 `{status: 'valid' | 'invalid' | 'inconclusive', reason, message, checkedAt, cached}`；要求登录、`AgentApp.read`，并有 `AgentApp.create` 或 `AgentApp.update`（超管放行）。只允许服务端已保存、启用、有密钥且模型在对应目录的目标；不接收客户端 URL/密钥，不返回供应商原始错误。
- 识图最多等 30 秒，生图最多等 90 秒；每员工同时一个测试，每分钟最多 6 次实际调用。同一员工/能力/配置的已完成结果缓存 60 秒；账号端点、密钥或模型变更后不复用旧结果。均为有界进程内保护，多实例不共享。模型测试与聊天并发配额独立，不批量扫模型、不自动重试，关闭页面也不能保证供应商停止处理或计费。刷新候选不是强制绕过缓存；未知结果重试前可核实供应商记录。

此次测试功能不新增数据库字段/迁移，部署更新前后端即可；模型引用能力本身仍依赖前述既有媒体迁移。

### 生图下拉为空时去哪里配置

来源已经接通，候选是**所选账号的「生图模型」专用目录**，而不是普通文本模型列表或视觉识别模型列表。账号还必须启用、有密钥，并填写完整「生图接口地址」。下拉为空仅表示没得到满足这些配置条件的候选，不能证明供应商没有生图模型，也不能证明账号已经开通了生图权限。

例如阿里云百炼提供 Qwen-Image 同步接口，可按[官方 Qwen-Image API 文档](https://help.aliyun.com/zh/model-studio/qwen-image-api)核对该账号实际可用的 `qwen-image-2.0` / `qwen-image-2.0-pro` 等模型及地域/业务空间。把实际模型登记到「大模型账号 → 生图模型」，协议选「阿里云 DashScope 同步多模态生图」，填写文档对应的完整 `/api/v1/services/aigc/multimodal-generation/generation` 地址，保存后回 Agent 页刷新并测试。不要把所有百炼生图模型都当成同一协议；异步接口、视频接口和其他不同请求契约不在当前接入范围。

本次只用模拟供应商自动验证，没有读取实际账号密钥或发送真实付费测试；实际账号是否可用，以配置后的测试和供应商开通状态为准。

### 数据、权限与费用保护

- 前后端字段：`agent_apps.mediaModels = { vision: {providerId,model} | null, imageGeneration: {providerId,model} | null }`。模型账号新增 `imageGenerationModels`、`imageGenerationProtocol`、`imageGenerationApiUrl`。原账号密钥不复制到 Agent 配置、消息或执行记录。
- 前端发送 `content/clientMessageId/imageId?`，不再传模式；后端暂时接收旧 `mode` 字段以兼容旧客户端，但不将其作为执行依据。媒体模式由服务端意图识别决定。图片只允许绑定本人当前会话；客户端不能指定供应商 URL 或通过其他人的图片 ID 识图。
- `POST /agent-workspace/sessions/:id/images` 上传，`GET /agent-workspace/sessions/:id/images/:imageId` 读取，继续要求登录、`AgentWorkspace.read`、本人会话和当前应用使用权限。即使管理员也不能借此接口读取他人的会话图片。
- 新表 `agent_images` 私有保存二进制及归属，不写公开 uploads，不将 Base64 放入消息 JSON；默认查询不加载图片二进制。浏览器通过带鉴权的请求取得 Blob，切换/卸载后释放临时 URL，服务端禁止缓存。
- 输入单图 ≤ 5 MB，每会话最多上传 50 张；输出单图 ≤ 10 MB，模型 JSON ≤ 16 MB。检查图片字节签名，不接受 SVG/非图片。数据库 `max_allowed_packet`、反向代理上传限制应覆盖这些上限（数据库建议至少 32 MB）。图片随数据库备份；本版不自动清理历史、未发送或停止后留下的未引用图片，部署方需制定保留与清理策略。
- 供应商返回的图片 URL 仅接受 HTTPS 443，拒绝重定向、私网/特殊 IP；将校验后的公网 IPv4 固定给连接以防 DNS 重绑定，不向图片 CDN 转发账号密钥。暂不支持仅 IPv6 或必须跳转的下载地址。
- 保留消息幂等号、员工/应用并发上限和总超时。意图分类计入同一轮文本尝试预算，最多尝试两个已选文本模型；分类本身也消耗 Token，后续不重置总超时。每次实际图片执行只请求一次图片模型，**图片失败、超时或停止不自动重试/切换**；重复同一消息 ID 恢复原执行记录，不重新分类或生图。手动发送一条新消息是新的付费请求。分类阶段停止不取消已有业务草稿，晚到分类结果不得继续调用图片模型。
- 真正请求时显示“正在识别图片并理解内容 / 正在生成图片”；保存实际回执后显示完成。结果、助手消息和成功终态同事务提交，与停止/失败采用条件更新，不允许迟到结果复活已停止任务。
- 停止/超时会中断当前进程的网络请求，并阻止晚到结果显示；不能保证供应商停止计算或免除费用。多实例时取消信号不跨进程传播，但数据库终态仍阻止结果复活。程序崩溃、网络断开等未知结果需核实供应商账单后再手动发起新请求。

### 验收建议

1. 优先顺序/均衡策略下不再显示禁用的轻量/复杂组；切换到意图策略后显示两组并要求填写。
2. 分别设置、保存、重新打开两种媒体引用；清除一个不影响另一个。两个候选列表均只包含所选账号；手动换账号清空旧引用，编辑回显不清空。停用账号/移除模型后执行应明确报配置错误，历史跨账号引用不可执行。
3. 在输入框粘贴实际图片（也测试纯文字、混合图文、多张和超限图片），提问后刷新历史，确认用户图与识别结果存在；用另一账号/会话引用该图片应失败。输入“如何生成图片”“不要生图”“只写提示词”不应调用生图模型；明确请求创作时才调用。缺图或编辑参考图应追问/说明限制。
4. 分别使用实际已开通的 OpenAI 兼容或 DashScope 同步模型生成一张图片；确认真实预览、历史回显、执行阶段与结果一致。
5. 测试超限、无效文件、HTTP 429、超时、停止以及重复消息 ID；无自动重复调用，无“停止后又成功”，无自动业务入库。

自动验证使用模拟供应商/仓库和网络边界，不发真实付费请求；真实账号联调及浏览器验收需配置后执行。

注意：回滚媒体迁移会删除 `agent_images` 表及其图片数据，回滚前必须先备份。

## 模型主动调度

编辑 Agent 应用 → 模型列表（最多 5 个）→ 模型调度策略：

轻量/复杂模型组仅在“按意图与需求复杂度”策略下显示，其余策略给出切换说明；媒体模型独立配置，不参加这些文本模型分组和重试。

| 策略 | 选型规则 | 使用边界 |
| --- | --- | --- |
| 优先顺序 | 首个健康模型优先，失败尝试后续模型 | 兼容旧配置，不主动摊分成功请求 |
| 均衡使用 | 优先当前进行中调用较少的模型，同负载优先更久未使用的模型 | 新建表单默认，可主动分散请求，但不是按真实余额加权 |
| 按意图与需求复杂度 | 从轻量组调用分类器，结合当前问题和最近对话，识别 chat/query/write/analysis 与 simple/complex；普通简单任务走轻量组，复杂或分析任务走复杂组 | 管理员指定两组，不从模型名称猜测性能；组内均衡，首选组不可用时尝试其它已选模型 |

- 分类器不能选择未授权模型、工具、URL 或更改权限。仅文本复杂度分类失败时保守走复杂组；涉及媒体分流时格式失败不触发图片或业务工具。两类分类最多尝试两个模型，执行阶段复用本轮分类，不循环重新识别。没有媒体能力的确定性操作保持原行为；开启媒体后聊天请求先分类，会增加一次正常文本阶段调用。
- 配置 `modelRouting` 字段在前后端保持一致：`strategy`、`simpleModels`、`complexModels`、`maxAttempts`（3～20）、`attemptTimeoutSeconds`（3～120）、`cooldownSeconds`（5～3600）。模型组必须是已选模型的子集；选择 intent 必须填写两组，同一模型可在两组中，但这不会形成能力分层。组名不构成授权。
- 每次模型阶段受单次超时与本轮总超时共同约束，通过已有 AbortSignal 中止模型网络请求，并预留备用时间。所有分类/规划/回答阶段重试合计不超过上限，不无限轮询冷却模型。不重复执行业务写入，写入仍只在确认事务中发生。
- 429、超时、临时故障会进入冷却；额度不足至少冷却 10 分钟，后续请求跳过它；上下文过长和分类格式错误不全局熔断模型。密钥或账号余额明确异常会停止同账号重试，提示管理员处理。403 可能是单模型访问限制，不认定整个账号失效。
- 健康状态和负载为当前后端进程内按账号/模型共享，重启清空；多实例暂不共享调度状态，若扩容需接 Redis 等共享协调。未接供应商真实配额查询，也不跨账号切换，不能保证永不耗尽共享 Token/余额。
- 「Agent 执行记录」显示策略、识别意图/复杂度、实际模型、尝试阶段、结果及规范化失败原因；用量仅记录供应商已返回的 Token，缺失不记成零。不记录密钥或原始供应商错误。阶段上限不等于底层 API 请求次数，知识问答内部可能含附加模型步骤，其原有配置保持不变。
- 已有应用不自动改策略或新增工具。管理员可选 intent 并分别指定已验证可用的轻量/复杂模型。新建 UI 默认 balanced；API 未传策略时兼容 priority。详情页可核对保存的调度参数。

ID 必须来自真实查询、员工明确输入或表单选择，模型不应猜测。分类未知时先生成待补充草稿，再从表单分类下拉选择。

当前每轮处理一个业务动作；“先查，没有就新增”先展示查询结果，员工再决定是否生成草稿。不是多步骤自动循环执行器，不会批量落库。查询仅按业务服务已有条件部分匹配，未实现额外的向量业务搜索。

仅保留原两个工具的历史应用继续使用兼容流程；选择通用工具后启用结构化语义规划。已有 SKU 草稿、回执和 `product.query` 均保持兼容。

## 运行流程与安全边界

1. 取当前应用已选、指令已启用且可聊天调用、执行器已接通的工具交集，再核对员工权限和写入开关。
2. 模型只返回受约束 JSON：回答、追问或一个白名单工具及参数。非法 JSON、未知工具、越权动作不能进入业务执行。
3. 查询参数先经字段白名单、类型和原 DTO 校验，再直接调用注入的业务 Service；页大小最大 20，不执行模型/数据库配置给出的任意 URL 或方法。
4. 返回字段也走显式投影，避免实体以后新增内部字段时自动泄漏。正文过长标注截断；历史查询上下文限制长度。
5. 新增先存 Agent 草稿；后端返回字段名、中文标签、必填项、类型、枚举/关系选项、业务提示，前端复用 Form 自动生成编辑表单。缺失字段或不合法数据只能待补充。
6. 最终确认再次核对应用和业务权限、草稿归属、版本及状态。通用写入锁定草稿，业务记录、执行回执、草稿状态、聊天回执在同一数据库事务中保存；重试按幂等键返回原结果，已提交草稿不能用新键重复录入。
7. 业务失败先回滚，再记失败回执，不展示录入成功。员工修改草稿后版本变化，前端生成新的确认键；网络超时则保留原键查证，不能盲目重新提交。

SKU 沿用既有专用 `agentOperationKey` 幂等保存与回执核实机制；其他模块不增加业务表幂等列，使用 Agent 草稿锁和统一事务。

## 后续新增普通业务模块

不是扫描所有 Controller 自动放权。模块仍按 AGENTS 的 Demo 流程创建；接入 Agent 只需补声明和服务绑定，无需复制聊天、草稿、确认和 UI。

1. 在 `server/src/ai-command-definitions/ai-command-definitions.constants.ts` 登记真实查询/创建参数、接口路径和权限。仅标记安全的 `list/detail/create` 可聊天调用。
2. 在 `server/src/agent-apps/agent-business.registry.ts` 的 `AGENT_BUSINESS_MODULES` 登记模块名称、权限前缀、管理路径、业务边界提示；特殊只读字段放入 `AGENT_BUSINESS_READ_FIELDS`。字段中文标签优先使用 schema 的 `title`，其次复用现有模块元数据。
3. 在 `AgentBusinessService` 的 `adapters` 中绑定原 Query/Create DTO 及 `list/detail/create` 服务方法。创建方法必须接受并使用传入的 `EntityManager` 保存全部相关业务数据；不得绕回默认 Repository 或自行提前提交事务。
4. 在 `AgentAppsModule` 导入对应业务模块并确保导出 Service。注册没有对应适配器时应失败，不允许把“已登记”伪装成“可执行”。
5. 复用测试模板，验证权限交集、DTO、结果投影、缺字段草稿、确认/幂等和业务失败回滚。高风险业务必须单独评估，不能套用默认开放策略。

核心文件：

- `agent-business.registry.ts`：模块与安全字段声明、工具描述。
- `agent-business.service.ts`：DTO 校验、服务绑定、字段投影和业务提交。
- `agent-business-plan.ts`：模型结构化输出解析及工具白名单。
- `agent-workspace.service.ts`：会话、规划、草稿、确认、事务与回执编排。
- `AgentDraftCard.vue` / `AgentBusinessQueryCard.vue`：通用编辑和只读结果展示。

## 验证与尚需人工验收

单元测试不连接数据库或真实模型；事务测试使用内存事务桩验证编排，不能代替 MySQL 故障注入测试。部署后请用测试应用逐项验证七类模块，重点验收不同模型的 JSON 规划质量、分类/产品选择、确认后记录回显、重复点击和断网重试。调度还需实测简单查询/复杂分析选型、模型限流/超时回退、同账号额度耗尽，以及执行记录中的模型轨迹。

知识库“保存成功”不等于“已索引、可检索”；标准问答“保存成功”不等于“已审核发布”。上线前仍应在对应管理页面完成后续步骤。
