# 知识库检索配置

本文档对应当前系统的「知识库检索配置」页面与 `knowledge_retrieval_configs` 配置。它决定 AI 聊天在什么范围内检索、如何融合排序，以及是否复用短时间内的会话知识库上下文。

## 新建配置默认值

| 字段 | 默认值 | 说明 |
| --- | ---: | --- |
| 配置名称 | — | 必填，由管理员填写 |
| 检索模式 | `hybrid` | 全文检索与向量检索并行 |
| 知识库范围 | 全部启用知识库 | 未选分类和文档时生效 |
| 召回上限 | `6` | 最终最多选入回答上下文的候选片段数 |
| 最低相关度 | `0.35` | 低于该分数的候选会被过滤 |
| RRF K | `60` | 候选融合排序时的排名衰减参数 |
| 文本权重 | `0.8` | 全文检索在融合中的权重 |
| 向量权重 | `1` | 向量检索在融合中的权重 |
| 上下文有效期（分钟） | `15` | 仅在有效期内复用上一轮命中的知识库 |
| 启用重排 | `true` | 默认对初步召回结果进行 AI 二次排序 |
| 重排 AI 配置 | 当前可用聊天配置 | 未指定时由后端自动绑定 |
| 是否启用 | `true` | 停用后不能被聊天应用使用 |

> 旧配置可能仍保存 `topK=10`、`minScore=0` 或关闭重排等历史值。它们不会因升级被强制改写，应在后台按业务需要逐项调整。

## 知识库范围规则

- 不选择分类且不选择具体文档：检索全部已启用知识库。
- 只选择分类：检索该分类下的已启用知识库。
- 只选择具体知识库：仅检索这些知识库。
- 同时选择分类和具体知识库：两者取并集，不是交集。
- 已停用的知识库不会参与检索，即使其 ID 被历史配置保存。

## 推荐保存入参

以下示例适合通用客服场景。`rerankAiFeatureConfigId` 传 `null` 时，后端会自动选择当前可用的聊天 AI 配置；若没有可用聊天配置且启用重排，保存会被拒绝。

```json
{
  "name": "通用知识库检索",
  "retrievalMode": "hybrid",
  "categoryIds": [1, 2],
  "knowledgeBaseIds": [10, 11],
  "topK": 6,
  "minScore": 0.35,
  "rrfK": 60,
  "textWeight": 0.8,
  "vectorWeight": 1,
  "sessionContextTimeoutMinutes": 15,
  "enableRerank": true,
  "rerankAiFeatureConfigId": null,
  "isEnabled": true,
  "description": "客服默认知识库检索策略"
}
```

保存成功后，返回数据中的 `rerankAiFeatureConfigId` 与 `rerankAiFeatureConfigName` 会是实际绑定的聊天配置。

## 实际检索流程

```text
确定配置范围
  → 判断是否为知识库清单问题
  → 判断会话上下文是否仍在有效期
  → 路由到明确知识库 / 当前会话知识库 / 全部范围
  → 全文与向量并行召回
  → 加权 RRF 融合
  → AI 重排（启用时）
  → minScore 过滤
  → 跨知识库抑制与片段选择
  → 按文档原分片顺序组装完整上下文
```

### 会话上下文有效期

- `15`：在最近一次知识库检索后的 15 分钟内，未明确点名新知识库的追问优先沿用上一轮命中的知识库。
- 超过有效期：当前提问按新问题处理，不拼接上一轮检索问题，也不锁定上一轮知识库。
- `0`：关闭知识库上下文复用，每次都按独立新问题检索。
- 有效期内的粘性检索没有任何合格结果时，系统会自动用**当前问题原文**在该配置的全范围内重新检索，无需刷新页面或新建会话。

### 重排

重排不是重新检索，而是对融合后的候选结果进行第二轮语义排序。系统最多将前 24 个融合候选交给重排 AI；重排成功后，最终分数约由 80% 重排分和 20% 融合分组成。重排调用失败或返回无法解析时，系统会自动回退到 RRF 融合结果。

### RRF K

RRF（Reciprocal Rank Fusion）用全文检索排名和向量检索排名共同计算融合分。`rrfK` 越大，各名次之间的差距越平缓；默认 `60` 是通用、稳健的取值。单一路径检索时，它仍参与该路径候选的排名衰减；它不是最低相关度阈值。

## 调参建议

| 场景 | 建议 |
| --- | --- |
| 知识库内容相似、易串库 | 保持或提高 `minScore`，建议从 `0.35` 开始；开启重排 |
| 答案缺少相邻上下文 | 将 `topK` 逐步调到 `8`，不要直接大幅提高 |
| 问题需要精确标题、编号、专有名词 | 保持 `hybrid`，文本权重可略高于默认值 |
| 文档表述多样、同义问法多 | 保持向量权重 `1` 并开启重排 |
| 用户常隔较久再回到历史会话 | 将上下文有效期设为 `10–15` 分钟；或设为 `0` 完全关闭复用 |

## 数据库升级

若部署版本包含会话有效期功能，需执行迁移：

```text
server/src/migrations/1788642000000-AddKnowledgeRetrievalSessionTimeout.ts
```

该迁移会为检索配置补充 `sessionContextTimeoutMinutes`（默认 `15`），并为聊天会话补充最后检索时间，用于后端判断是否复用知识库上下文。
