# 联网搜索能力优化方案

整理日期：2026-10-25

计划整改日期：2026-10-26

实施状态：待实施，当前代码仍按现有规则运行。

联网搜索采用“平台自有模型内置规则，第三方模型使用专用卡片”的接入方式。腾讯混元、阿里百炼千问中已确认支持搜索的型号，由后端维护请求格式和来源解析；DeepSeek、GLM、Kimi 等第三方型号通过具体模型的联网搜索卡片接入。明天的整改重点是收紧现有默认规则，避免仅凭账号属于腾讯或阿里，就向所有模型发送同一种联网请求。

## 一 默认支持范围

账号平台、模型归属和模型能力分别判断。账号平台由已保存的接口域名识别；模型归属及联网支持范围由后端明确的能力清单维护。账号中登记了某个模型，只表示可以选择该型号，不能证明它支持搜索。

| 账号平台与模型                                           | 默认处理                                              | 没有专用卡片时                       |
| -------------------------------------------------------- | ----------------------------------------------------- | ------------------------------------ |
| 腾讯 TokenHub 上已纳入能力清单的混元文本模型，首批 `hy3` | 使用后端内置的混元联网适配器                          | 可以按内置规则执行并核验来源         |
| 阿里百炼上已纳入能力清单的千问文本模型                   | 使用后端内置的千问联网适配器                          | 可以按内置规则执行并核验来源         |
| 腾讯或百炼托管的 DeepSeek、GLM、Kimi 等第三方模型        | 匹配该平台、完整模型编码及 `webSearch` 场景的专用卡片 | 提示配置专用卡片，不发送付费搜索请求 |
| 自有模型中尚未确认支持搜索的新型号或特殊类型             | 按具体型号核实，可通过专用卡片调试                    | 不自动套用整个系列的联网能力         |
| 尚未接入的其它独立平台或自定义代理                       | 后续补充平台适配器及来源解析                          | 保留普通调用，暂不开放默认联网       |

腾讯账号下的千问仍属于第三方模型；百炼账号下的 DeepSeek 同样属于第三方模型。相同模型在不同承载平台的卡片分别维护，不能跨平台复用协议或凭据。

默认支持的是一套经过确认的调用格式和模型范围，实际能否联网仍取决于模型、账号开通情况和本次返回结果。新增版本优先扩展后端能力清单，不要求为已确认兼容的每个快照重复建卡片；不以 `hy*`、`qwen*` 等宽泛前缀直接放行所有型号。

## 二 调用规则

每次联网执行统一采用以下顺序：

1. 检查账号启用状态、密钥、当前平台及业务文本模型目录，保持用户所选的完整模型编码。
2. 查找“当前账号平台＋当前模型＋联网搜索”专用卡片。存在且启用时优先使用；存在但停用时直接阻止调用。
3. 没有专用卡片时，查询平台自有模型的联网能力清单。命中才使用系统内置适配器；第三方或未覆盖型号返回缺少专用配置的提示。
4. 校验实际协议、地址和来源解析方式，发送一次请求，不自动换模型、换协议或重投。
5. 核对真实搜索执行及来源数据，再决定是否可以作为热点搜索结果。

删除专用卡片后，自有且在清单中的模型可以恢复内置规则；第三方型号回到“需要专用卡片”。普通聊天、识图和向量的既有匹配方式不随本次联网整改一起收紧。

“推荐自建卡片”是第三方模型的配置引导；实际联网执行需要已启用的专用卡片。普通调用卡片不能代替联网搜索卡片，也不增加一个“缺卡时试用默认接口”的开关。

## 三 后端适配器与能力清单

### 平台自有模型

混元适配器首批使用 `hy3` 的 Responses 搜索格式：`/v1/responses`，通过 `tools` 声明 `web_search`。千问适配器保留百炼 `/compatible-mode/v1/responses` 和相应搜索工具参数，只覆盖官方说明支持该方式的千问型号及版本。腾讯的 Chat 与 Responses 搜索格式不同；百炼 Responses 也只支持部分型号，能力清单需随官方支持范围维护。[腾讯联网搜索](https://cloud.tencent.com/document/product/1823/132358)、[百炼联网搜索](https://help.aliyun.com/zh/model-studio/web-search)

后端清单至少表达适用平台、模型编码或有明确边界的版本规则、调用协议、接口路径、请求构造和来源解析器。它是代码中的维护结构，不新增数据库字段或配置表单。尚未确认的新版本不能因为名字相似自动继承能力。

腾讯继续使用现有轻量搜索和已验证可接受的 `low` 参数，百炼保留自己的思考参数；两家参数不混用。其它型号的专用卡片若需要现有协议尚不支持的参数或响应结构，先补相应适配器，再使用该卡片，不在卡片中开放任意代码执行或随意映射响应字段。

### 第三方模型

专用卡片复用现有字段：`platformType`、`modelCode`、`functionType=webSearch`、`protocol`、`apiPath`、同步执行方式和 `isActive`。账号只提供基础地址与认证信息，不恢复账号中的各功能专用地址字段，也不增加草稿、备注或能力永久认证字段。

腾讯托管的 DeepSeek 即使使用平台 Chat 搜索格式，也放在模型专用卡片中。已有官方依据的精确型号可以提供预设，管理员可直接测试、编辑或停用；未知版本由管理员按该平台官方文档建立卡片并调试，不通过别名替换放行。官方预设补缺时保留人工编辑、停用和软删除记录。

本轮第三方接入首先覆盖当前已支持的腾讯、百炼托管场景。其它独立厂商需要另行完成平台识别、请求构造和来源解析，不能仅创建 `custom` 卡片就绕过现有平台及同源检查。

现有搜索规则 `-7` 收窄为千问适用范围，`-8` 收窄为混元适用范围；DeepSeek 系统规则 `-9` 移出可选系统卡片，编号不复用。已有负数卡片编号和临时测试历史不能被映射到另一条规则；旧记录可继续说明原路径，新请求提示该系统规则已调整，并引导进入专用卡片。

## 五 既有配置兼容

继续使用现有 `webSearchMode`：腾讯账号保留 `tokenhubSearch`，百炼账号保留 `bailianResponses`，原本关闭的配置继续保持 `disabled`。这些值表示账号平台的搜索接入方式，具体模型最终使用内置规则还是专用卡片由后端解析，不新增“自有或第三方”开关。旧 `bailianChat` 保持现有不可用提示。

不批量改写用户已保存的账号、模型、联网方式、启用状态或日程。第三方缺卡的历史配置仍可查看、关闭或改成不联网；启用保存及实际联网执行时给出缺卡原因。已有生效的专用卡片继续使用，不能因整改被覆盖或复活。

升级前先盘点受影响的配置和专用卡片。对于已确认的第三方型号，走现有补缺逻辑提供预设；人工停用或软删除过的记录继续尊重原操作。其它型号明确列出待配置项，不通过补建未知接口静默恢复付费搜索。运行中的旧任务保持原任务标识，后续执行遇到缺卡时如实失败，不换型号重跑。

本轮不自动给 Agent、聊天或内容生成增加联网功能。现有需要联网的业务继续共用解析与来源核验；普通平台采集、网易固定接口、混合模式直读和普通 AI 推荐保留既有行为。

## 六 结果核验和用户提示

接口地址正确或返回 HTTP 200，只能说明请求有返回。腾讯 Responses 的部分兼容模式会丢弃内置搜索工具而不报错，因此不能把普通回复当作联网成功。[腾讯 Responses 工具说明](https://cloud.tencent.com/document/product/1823/135873)

沿用现有来源核验：百炼验证完成的搜索调用及 `action.sources`；腾讯 Responses 验证完成的搜索调用和结构化引用，腾讯 Chat 验证 `search_results`。没有真实来源时，热点业务不能用模型记忆、正文链接、用量计数或推测日期补成搜索结果。

| 情况                       | 用户端提示原则                                                                           |
| -------------------------- | ---------------------------------------------------------------------------------------- |
| 自有型号命中内置规则       | 显示已匹配内置接口；静态检查不宣称联网成功                                               |
| 第三方型号缺少联网卡片     | 指出当前模型及“第三方配置 → 模型厂商调用接口 → 新增联网搜索专用卡片”，说明未发起实际测试 |
| 专用卡片停用或协议不兼容   | 显示具体配置原因，不能回退默认搜索                                                       |
| 实际返回有效搜索来源       | 提示本次联网测试成功，保留所用账号、模型和实际路径                                       |
| 返回 200 但没有搜索来源    | 提示无法确认联网成功，核对模型支持、账号联网服务及本次是否执行搜索                       |
| 明确的费用、额度或权限错误 | 沿用相应中文错误，不将所有无来源情况判断为欠费或未开通                                   |

AI 功能配置继续保留用户切换模型时直接测试的现有交互，不新增勾选项。缺卡先提示，配置有效才发送一次测试；打开、回显和保存不发付费请求，关闭不重新提交或取消已受理的供应商任务。接口卡片仍由用户明确点击开始才测试。

2026-10-25 对 Hy3、DeepSeek V4 Flash、GLM-5.3 的两轮短请求，修正参数后均返回 200，但没有可核验的搜索来源。该结果保留为未确认联网成功，不能作为能力清单的成功验收记录。明天整改完成后，真实联网验收需使用已开通服务的账号另行执行，不自动重放这些请求。

## 七 明天的整改顺序和验收标准

| 顺序 | 工作                             | 验收要求                                                                                                                             |
| ---- | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 1    | 盘点旧配置并建立自有模型能力清单 | 腾讯仅混元、百炼仅千问的已确认型号进入默认搜索范围，账号平台不代替模型归属判断                                                       |
| 2    | 收紧系统规则和匹配逻辑           | Hy3 及清单中的千问可无专用卡匹配；腾讯 GLM、DeepSeek、百炼托管第三方和未知型号无卡时不发送搜索请求                                   |
| 3    | 整理第三方预设与历史覆盖         | 官方已确认的 DeepSeek 联网预设可补缺；现有卡片优先，停用和软删除记录不被恢复                                                         |
| 4    | 对齐配置检查和执行入口           | 配置、系统卡片候选、功能测试及热点任务对同一账号和模型解析一致，模型编码原样传递                                                     |
| 5    | 更新页面提示与规范               | 页面说明默认范围与专用卡片用途，不将“配置匹配”显示为“联网成功”                                                                       |
| 6    | 静态检查和针对性回归             | 覆盖无卡、专用覆盖、停用、软删、跨平台、新版本、空模型目录、无来源、费用错误和历史配置关闭等分支；按项目规则不自动 build 或启动服务  |
| 7    | 真实联网验收                     | 使用已开通服务的账号分别验证混元内置、千问内置及一个第三方专用卡片，必须返回可核验来源；明确记录未开通、无结果和模型不支持的实际原因 |
| 8    | 记录整改结果并提交               | 同步设计规范、文件清单和 CHANGELOG，仅提交本次改动，不夹带用户已有未提交文件                                                         |

整改完成的标准是：自有模型默认规则边界明确、第三方专用接入可调试、实际来源核验一致，且原有不联网分析和普通调用可继续使用。
