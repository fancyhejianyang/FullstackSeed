# MinerU 解析实现原理

本文说明知识库如何使用 MinerU 完成第三方文档解析。MinerU 的职责是把复杂文件转换成可保存、可检索的正文（通常是 Markdown）；它不替代知识库后续的分片、索引和聊天检索。

## MinerU 在系统中的位置

```text
原始文件
  ↓
AI 模型解析（配置启用 MinerU 时优先交给 MinerU）
  ↓
Markdown / 文本正文
  ↓
自动或手动分片
  ↓
全文与向量索引
  ↓
AI 聊天检索
```

在知识库列表中，管理员选择「AI 模型解析」后，系统会按文件类型读取 OCR 或文档解析功能配置；只要其中已启用 MinerU，且当前知识库有非文本文件地址，系统会优先走 MinerU。文档详情页也提供直接选择「MinerU 解析」的入口，用于对已有文档重新解析。

因此，MinerU 是 AI 解析链路中的一个配置选项，而不是手动解析的后备步骤；手动 PDF 的 OCR 兜底仍由系统本地 OCR 完成。

## 适用场景

MinerU 更适合需要识别文档结构而不只是读取连续文字的文件，例如：

- 扫描型 PDF、图文混排 PDF；
- 含复杂表格、公式、章节层级的资料；
- 手动解析结果缺页、段落顺序错乱或表格信息丢失的文件；
- 需要以 Markdown 形式保留标题层级、列表等结构的资料。

它不是每份文件都必须使用。对于 TXT、Markdown、普通 Word 和有稳定文字层的 PDF，手动解析一般更快、成本更可控，也更便于复现。

## 使用前需要具备的配置

要让 MinerU 真正生效，需要同时满足以下条件：

| 配置或条件 | 作用 |
| --- | --- |
| 已启用的 MinerU 配置 | 提供服务地址、访问令牌、模型版本、轮询间隔和超时时间 |
| 对应的 AI 功能配置启用 MinerU | OCR 或文档解析功能配置必须绑定可用的 MinerU 配置 |
| 文件地址可被 MinerU 读取 | 系统会将文件地址转换为可读取地址；私有存储需要生成足够有效期的签名地址 |
| 原文件仍可访问 | 解析期间文件不能被删除、移动或提前过期 |

MinerU 配置可以控制是否启用 OCR、公式识别和表格识别。访问令牌属于敏感信息，只应由管理员在配置页维护，页面展示和日志中不应暴露明文。

## 完整处理流程

```text
选择 AI 模型解析 / MinerU 解析
  ↓
系统校验功能配置、MinerU 配置和文件地址
  ↓
为私有文件生成可读取的临时地址（如需要）
  ↓
创建 MinerU 解析任务，记录任务 ID
  ↓
按配置的轮询间隔查询任务状态和进度
  ↓
成功：读取 Markdown 或结果包中的可读正文
失败/超时：保存失败原因
  ↓
标准化正文并写入知识库文档
  ↓
清除旧分片，状态变为“已解析，等待分片”
```

MinerU 的结果可能直接携带 Markdown，也可能返回结果包地址。系统会从结果包中提取可读的 HTML、Markdown 或文本内容，并保留可识别链接，使它们能继续作为知识库正文被分片和检索。

解析任务以后台任务运行。任务执行时会同步更新「处理中 / 进度 / 失败原因」等状态；若服务重启时发现仍在处理且已记录任务 ID 的 MinerU 文档，系统会尝试继续查询该任务，而不是直接把它当作成功或丢弃。

## 解析完成后还要做什么

MinerU 返回 Markdown 不等于聊天已经能回答。正确的后续顺序是：

1. 在文档正文中抽查页数、标题、表格、公式和关键条款是否完整；
2. 执行自动分片，或进入详情页手动框选分片；
3. 执行索引，等待全文与向量数据完成；
4. 确认聊天应用绑定的检索配置覆盖该知识库，再做问答验证。

当前页面里称为「MinerU 分片」的自动分片入口，读取的是已解析正文和默认分片配置（长度、重叠、按段落/按长度、标题保留等）。它不会把原文件再次提交给 MinerU；修改分片参数后需要重新分片并重新索引。

## 常见失败原因

| 现象 | 常见原因 | 处理建议 |
| --- | --- | --- |
| 创建任务失败 | MinerU 配置未启用、令牌无效、服务地址或接口路径不正确 | 检查 MinerU 配置和访问令牌，确认只保留正确的可用配置 |
| MinerU 无法读取文件 | 本地 `localhost` 地址、私有对象未签名、链接已过期或文件被删除 | 使用系统存储生成的可读取地址；确保签名有效期覆盖解析时间 |
| 长时间处理中或超时 | 文件过大、服务排队、轮询间隔或超时时间不合适 | 查看任务进度与服务端日志；适当提高超时时间后重新提交 |
| 成功但正文为空 | 第三方未返回可读 Markdown/结果包，或文件本身不可识别 | 查看处理结果中的原始错误信息；换用清晰原文件或手动解析验证 |
| 正文不完整、表格错位 | 原件质量、复杂布局或第三方模型能力限制 | 抽查关键页；调整 MinerU 的 OCR/表格/公式选项，必要时补充人工文本 |
| 解析成功但聊天找不到 | 还未分片、还未索引，或聊天检索范围不包含该知识库 | 按「解析 → 分片 → 索引 → 检索配置」顺序排查 |

## 选型建议

| 文档情况 | 优先选择 |
| --- | --- |
| 已有干净的纯文本 | 手动解析 |
| 普通 Word、制度文件、文字层完整的 PDF | 先手动解析并抽查 |
| 扫描 PDF、图文混排、表格公式较多 | MinerU 解析 |
| 手动解析已得到完整正文，但回答缺少后半段 | 不必重跑 MinerU；先检查分片大小、召回数、索引和检索配置 |

## 关键认识

- MinerU 解决的是「如何从原始文件得到更完整的正文」；
- 分片解决的是「如何把正文切成适合检索的片段」；
- 索引和检索配置解决的是「聊天时能否召回正确片段」。

这三类问题要分别验证。比如一份 PDF 在正文页已经完整，聊天回答却漏掉第四点，优先检查分片和检索；反过来，正文页本身就缺第四点，才应回到手动解析或 MinerU 解析进行处理。
