# 知识库检索配置字段说明

本文档描述当前 API、前端表单和后端实体共用的字段契约。配置对象采用 camelCase；创建和更新接口均使用相同字段名。

## 配置字段

| 字段 | 类型 | 默认值 | 校验范围 | 说明 |
| --- | --- | ---: | --- | --- |
| `name` | `string` | — | 必填，最长 120 字符 | 配置名称，用于后台识别 |
| `retrievalMode` | `fullText \| vector \| hybrid` | `hybrid` | 三选一 | 检索模式 |
| `categoryIds` | `number[]` | `[]` | 每项为正整数 | 纳入检索的知识库分类 ID |
| `categoryNames` | `string \| null` | `null` | 返回字段 | 分类名称快照，主要用于展示 |
| `knowledgeBaseIds` | `number[]` | `[]` | 每项为正整数 | 纳入检索的具体知识库 ID |
| `knowledgeBaseNames` | `string \| null` | `null` | 返回字段 | 知识库名称快照，主要用于展示 |
| `topK` | `number` | `6` | 整数，`1–100` | 最终最多选入回答上下文的候选数 |
| `minScore` | `number` | `0.35` | `0–1` | 最低相关度；在重排（若启用）之后过滤 |
| `rrfK` | `number` | `60` | 整数，`1–500` | RRF 融合排序参数；单一路径时也参与该路径的排名衰减 |
| `textWeight` | `number` | `0.8` | `0–1` | 全文检索融合权重 |
| `vectorWeight` | `number` | `1` | `0–1` | 向量检索融合权重 |
| `sessionContextTimeoutMinutes` | `number` | `15` | 整数，`0–1440` | 会话知识库上下文有效期，`0` 表示不复用 |
| `enableRerank` | `boolean` | `true` | — | 是否使用 AI 对初步候选进行二次排序 |
| `rerankAiFeatureConfigId` | `number \| null` | 自动选择 | 正整数或 `null` | 重排所用的聊天 AI 功能配置 ID |
| `rerankAiFeatureConfigName` | `string \| null` | 自动回填 | 返回字段 | 已绑定重排 AI 配置名称 |
| `isEnabled` | `boolean` | `true` | — | 是否启用当前检索配置 |
| `description` | `string \| null` | `null` | 可选 | 配置说明 |

## 字段联动规则

### 范围字段

`categoryIds` 与 `knowledgeBaseIds` 是并集关系：只要命中任一选择条件的已启用知识库都可以参与检索。两者都为空时，范围为全部已启用知识库。

### 检索模式与权重

| `retrievalMode` | 实际调用 | 权重字段效果 |
| --- | --- | --- |
| `fullText` | 仅全文检索 | 仅全文结果参与，`vectorWeight` 不参与当前请求；`rrfK` 仍影响全文候选排名衰减 |
| `vector` | 仅向量检索 | 仅向量结果参与，`textWeight` 不参与当前请求；`rrfK` 仍影响向量候选排名衰减 |
| `hybrid` | 全文与向量并行 | 两侧结果按权重和 `rrfK` 共同融合 |

### 重排

- 新建配置默认 `enableRerank=true`。
- 启用重排且未提供 `rerankAiFeatureConfigId` 时，后端自动选择一个当前可用的聊天 AI 配置并回填 ID、名称。
- 启用重排但系统没有可用聊天 AI 配置时，保存失败并提示管理员先启用聊天配置。
- 关闭重排会清空 `rerankAiFeatureConfigId` 和 `rerankAiFeatureConfigName`。
- 重排异常不会中断聊天；系统保留 RRF 融合结果继续回答。

### 会话上下文

`sessionContextTimeoutMinutes` 不会传给模型供应商，也不是模型的 temperature、topP 等参数。它由后端在检索前使用：

1. 读取该会话的 `lastRetrievalAt` 和上一次命中的知识库。
2. 未超过有效期且本轮没有明确新知识库名称时，优先在上一知识库内检索。
3. 超过有效期、值为 `0`、或会话没有有效检索时间时，按新问题在配置范围内重新路由。
4. 若优先检索无合格结果，立即以当前问题原文回退到全部配置范围检索。

## 运行时会话字段

下列字段属于聊天会话状态，不是创建检索配置时的请求字段：

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| `activeKnowledgeBaseId` | `number \| null` | 最近一次可作为追问上下文的知识库 |
| `lastRetrievalQuery` | `string \| null` | 最近一次有效检索问题，可用于补全追问 |
| `lastRetrievalAt` | `datetime \| null` | 最近一次执行知识库检索的时间，用于有效期判断 |

当系统将本轮认定为新问题且没有命中时，会清除旧知识库缓存，避免下一轮继续受过期主题影响。

## 推荐请求示例

```json
{
  "name": "通用知识库检索",
  "retrievalMode": "hybrid",
  "categoryIds": [1, 2],
  "knowledgeBaseIds": [10, 11],
  "topK": 6,
  "minScore": 0.35,
  "rrfK": 60,
  "textWeight": 0.8,
  "vectorWeight": 1,
  "sessionContextTimeoutMinutes": 15,
  "enableRerank": true,
  "rerankAiFeatureConfigId": null,
  "isEnabled": true,
  "description": "客服默认知识库检索策略"
}
```

## 与旧版说明的差异

| 项目 | 旧示例 | 当前新建配置默认值 |
| --- | ---: | ---: |
| `topK` | `10` | `6` |
| `minScore` | `0` | `0.35` |
| `enableRerank` | `false` | `true` |
| `sessionContextTimeoutMinutes` | 未提供 | `15` |

旧记录会保留原有值，因此升级后应重点检查：检索范围、最低相关度、是否已启用重排、重排配置是否可用，以及会话有效期是否符合业务场景。
